# Church Calendar

A small, responsive calendar embed for Tokyo Union Church. It renders events from any number of public Google Calendars using FullCalendar Standard, lets visitors show or hide individual sources, and provides month-grid and list views. Its presentation mirrors Squarespace's spacious, editorial Calendar Block aesthetic while retaining Google Calendar as the source.

The project is a static Vite/TypeScript application. It has no backend, database, paid FullCalendar dependency, or runtime secrets.

## Requirements

- Node.js 24 or newer
- A Google Cloud browser API key with the Google Calendar API enabled
- One or more public Google Calendar IDs

## Local setup

```sh
npm install
cp .env.example .env.local
```

Add the domain-restricted browser key to `.env.local`:

```dotenv
VITE_GOOGLE_CALENDAR_API_KEY=your-key
```

Then add calendar IDs and presentation settings in `src/config.ts` and start the development server:

```sh
npm run dev
```

Calendar definitions with a blank `googleCalendarId` are ignored, so the project can be built before all sources are available.

## Calendar configuration

Each entry in `calendarDefinitions` supports:

| Field | Purpose |
| --- | --- |
| `id` | Stable internal and URL identifier |
| `label` | Visitor-facing filter label |
| `googleCalendarId` | Public Google Calendar ID |
| `color` | Event and filter color |
| `enabledByDefault` | Whether the source initially appears |
| `userToggleable` | Whether visitors receive a filter control |

The application remembers visitor choices in local storage. A `calendars` query parameter overrides both local storage and defaults:

```text
https://calendar.example.org/?calendars=church,groups
```

An empty value (`?calendars=`) starts with every source hidden.

## Google API key restrictions

The key is delivered to browsers and must not be treated as a secret. Restrict it in Google Cloud Console:

1. Set **Application restrictions** to **Websites**.
2. Add the production calendar host and local development origins as HTTP referrers.
3. Set **API restrictions** to **Google Calendar API** only.
4. Ensure every configured calendar is intentionally public.

## Commands

```sh
npm run dev        # local development
npm run test       # unit tests
npm run build      # type-check and production build
npm run preview    # serve the production build locally
npm run check      # tests followed by a production build
```

## Squarespace embed

Deploy the contents generated by `npm run build` to a static host, then add an iframe to a Squarespace Code Block:

```html
<iframe
  src="https://calendar.example.org/"
  title="Tokyo Union Church calendar"
  loading="lazy"
  style="width: 100%; min-height: 850px; border: 0;"
></iframe>
```

The final host and iframe sizing strategy can be selected when deployment is configured. The app opens in month-grid view at every screen size; visitors can switch to a month list when preferred.

## Architecture

- `src/config.ts` — calendars and application settings
- `src/main.ts` — FullCalendar setup, filters, persistence, and error states
- `src/source-state.ts` — testable calendar-source selection rules
- `src/styles.css` — responsive embed and FullCalendar theme
